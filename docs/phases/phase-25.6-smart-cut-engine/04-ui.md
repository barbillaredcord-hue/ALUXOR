# 04 — Interfaz de Usuario
# BR Material Studio

---

# Objetivo

El BR Material Studio deberá convertirse en el centro profesional para la optimización de materiales dentro de ALUXOR.

El usuario no debe sentir que está utilizando únicamente un optimizador de cortes.

Debe sentirse como un sistema profesional de planeación de fabricación.

---

# Filosofía

La interfaz debe ayudar al usuario a responder tres preguntas:

¿Estoy utilizando correctamente mi material?

¿Puedo reducir costos?

¿La solución realmente puede fabricarse?

Toda la experiencia deberá construirse alrededor de estas preguntas.

---

# Flujo General

Seleccionar material

↓

Configurar restricciones

↓

Generar propuesta

↓

Comparar soluciones

↓

Visualizar hojas

↓

Revisar métricas

↓

Aplicar cambios

---

# Vista Inicial

Antes de ejecutar la optimización el usuario deberá visualizar:

Resumen del material.

Cantidad estimada de hojas.

Área total.

Costo estimado.

Desperdicio estimado.

Configuración activa.

Esta información representa únicamente una estimación.

Nunca deberá confundirse con el resultado final.

---

# Botón Principal

El botón principal será:

Optimizar Material

Al ejecutarlo comenzará el proceso completo del Smart Cut Engine.

Durante el cálculo deberá mostrarse un indicador visual.

---

# Resultado

Al finalizar la optimización deberá mostrarse:

Cantidad real de hojas.

Cantidad de sobrantes utilizados.

Cantidad de sobrantes generados.

Porcentaje de aprovechamiento.

Área desperdiciada.

Tiempo de cálculo.

Estrategia utilizada.

---

# Vista de Hojas

Cada hoja deberá representarse gráficamente.

Cada pieza deberá mostrar:

nombre

medidas

orientación

grupo

material

Las piezas deberán visualizarse exactamente donde fueron colocadas.

---

# Colores

La interfaz deberá utilizar colores consistentes.

Ejemplo:

Azul

Piezas normales.

Verde

Piezas reutilizadas.

Amarillo

Sobrantes útiles.

Rojo

Advertencias.

Gris

Desperdicio.

Los colores deberán mantenerse consistentes en toda la aplicación.

---

# Zoom

El usuario podrá:

hacer zoom

alejar

centrar

desplazar

sin perder precisión.

---

# Información al pasar el cursor

Al posicionarse sobre una pieza deberán mostrarse:

Nombre

Dimensiones

Área

Material

Rotación

Grupo

Prioridad

Costo asociado

---

# Panel de Métricas

El panel lateral deberá mostrar siempre:

Hojas utilizadas

Sobrantes utilizados

Sobrantes nuevos

Área útil

Área desperdiciada

Aprovechamiento

Costo

Tiempo de optimización

Número de cortes

---

# Comparador

Cuando existan varias soluciones el usuario podrá compararlas.

Cada propuesta mostrará:

Aprovechamiento

Cantidad de hojas

Costo

Desperdicio

Cantidad de cortes

Tiempo estimado

El usuario podrá seleccionar la solución que prefiera.

---

# Advertencias

Las advertencias deberán ser visibles.

Ejemplos:

Una pieza no cabe.

La veta impide rotación.

No existen sobrantes compatibles.

Fue necesaria una hoja adicional.

Existe desperdicio elevado.

Nunca deberán ocultarse.

---

# Explicaciones

El sistema deberá explicar sus decisiones.

Ejemplos:

Se reutilizó un sobrante porque reduce el costo.

Se abrió una hoja nueva porque ningún sobrante era compatible.

La rotación fue bloqueada por la dirección de veta.

Estas explicaciones deberán ser claras y fáciles de entender.

---

# Vista de Desperdicio

Las áreas desperdiciadas deberán visualizarse.

No únicamente mostrarse como porcentaje.

El usuario debe identificar visualmente dónde se pierde material.

---

# Vista de Sobrantes

Los sobrantes reutilizables deberán mostrarse por separado.

Cada uno deberá indicar:

Dimensiones.

Área.

Material.

Identificador.

Nivel de reutilización.

---

# Configuración

El usuario podrá configurar:

Kerf.

Márgenes.

Permitir rotación.

Dirección de veta.

Tamaño mínimo de sobrante.

Prioridad de reutilización.

Todas estas opciones deberán actualizar la optimización.

---

# Confirmación

El resultado nunca deberá aplicarse automáticamente.

Siempre deberá existir un botón:

Aplicar Optimización

Hasta ese momento la cotización permanecerá sin cambios.

---

# Cancelación

El usuario podrá cancelar la optimización.

La cancelación nunca deberá modificar la cotización.

---

# Historial

Cada optimización podrá conservar:

Fecha.

Tiempo.

Estrategia.

Resultado.

Métricas.

Esto facilitará auditorías futuras.

---

# Responsive

La interfaz deberá funcionar correctamente en:

Escritorio.

Laptop.

Tablet.

En pantallas pequeñas las hojas podrán mostrarse verticalmente sin perder funcionalidad.

---

# Accesibilidad

La interfaz deberá respetar:

Contraste suficiente.

Navegación por teclado.

Indicadores visibles.

Textos legibles.

Los colores nunca deberán ser la única forma de comunicar información.

---

# Rendimiento Visual

La interfaz deberá permanecer fluida incluso con proyectos grandes.

No deberá congelarse durante la optimización.

El usuario siempre deberá conocer el estado del proceso.

---

# Objetivo Final

El BR Material Studio deberá ofrecer una experiencia comparable a la de software profesional de optimización industrial.

El usuario deberá comprender rápidamente:

Qué decidió el motor.

Por qué tomó esa decisión.

Cuánto material ahorró.

Qué desperdicio permanece.

Qué solución es la mejor.

Y únicamente después decidir si desea aplicar la optimización a la cotización.
